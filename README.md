# Coop field — котобитвы на общем canvas-поле

Агентам: карта репо и контракт комнаты — в [AGENTS.md](AGENTS.md), глубина (слои, зеркала, цель рефакторинга) — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Фронт — канвас-симулятор из [abnocw](https://github.com/ggaymelini/abnocw) + WebSocket-комната: до 30 котов,
ходьба WASD (та же раскладка на русской клавиатуре), стрелы-удары, скины, панель настроек, чат и боевой лог.
Сервер комнаты — авторитет клеток: двоих в одну клетку не сажает, отказы приходят событием `refuse`.

## Быстрый старт

```bash
npm install
# терминал 1 — комната (порт 3780)
npm start
# терминал 2 — фронт (http://localhost:3000)
npm run dev
```

Откройте `http://localhost:3000/?room=demo&name=Сырь` и вторую вкладку с другим `?name=`.
Комнаты: «Пивные гроты» (поле 10×6) и рисованная локация «Элизия Эйдес».

Тесты: `npm run test:queue` — очередь шагов (сервер поднимает сам); `npm run test:ws` — контракт комнаты,
нужен уже поднятый сервер (`npm start`, либо `WS_URL=ws://...`); `npm run test:unit` — юнит-тесты движка
(нужен node ≥22.6, на старых печатает SKIP); `npm run arch:check` — гейт архитектуры; `npm run check:protocol` и `npm run test:protocol-parity` — сверка док-таблиц
протокола и клиент/серверного паритета; `npm run check:landmarks` — актуальность чисел в доках.

## Что уже есть в игре

Эпохи после базовой сетки: редактор локаций с кистью и entry-клетками, террейн с обрывами и
заряжёнными прыжками, смена дня-ночи и погоды, мирный режим с манекеном и мишенью «РАБ»,
комната «тест» 19×7 «Элизия Эйдес», наборы спрайтов Malyshochki/Puzik и пиксельная отрисовка локации.

- Комната: `wss://coop.89-232-184-77.sslip.io` — VPS 89.232.184.77, systemd-сервис `coop-field`,
  **порт 8787** за nginx (локальный дефолт — 3780)

Мерж PR в `main` [gertha-puzik/coop-field](https://github.com/gertha-puzik/coop-field) — это деплой прода, поэтому прямой пуш в `main` запрещён (branch protection): изменения идут через ветка + PR. Мерж запускает Actions:

| Workflow | Когда стартует | Что делает / ловит |
|----------|---------------|--------------------|
| «Проверки» (ci.yml) | push в `main`, PRы по путям кода | typecheck, юнит-тесты, гейт архитектуры (≥800 строк), версия `ws` в двух lockfile, очередь шагов, синхронизация и паритет протокола, актуальность доков |
| «Фронтенд на Vercel и VPS» | изменения `src/`, `public/`, Next-конфига, зависимостей | `vercel deploy --prod` + rsync `out/` → `/opt/coop-field/www` |
| «Сервер комнаты на VPS» | изменения `server.js`, `scripts/`, `deploy/vps/` | rsync + `deploy/vps/apply.sh` (рестарт только если серверные файлы изменились, health-check после) |

Секреты в GitHub: `VERCEL_TOKEN`, `VPS_SSH_KEY` — в коде и логах их нет.

## Работа с ИИ

Проект рассчитан на разработку через ИИ-агентов — карта и правила уже готовы:

- **Агенты с доступом к файлам** (Cursor, Claude Code и т.п.) начинают с [AGENTS.md](AGENTS.md): карта кода, ворота качества, контракт комнаты.
- **Внешние чаты без доступа к файлам** (z.ai и подобные) — первым сообщением скормите [docs/AI-CONTEXT.md](docs/AI-CONTEXT.md):
  сжатое досье проекта (стек, деплой-контур, карта модулей, жёсткие правила, протокол работы через человека-посредника).
  Дальше вставляйте туда целые файлы и забирайте правки diff'ами.
- Процесс правок: ветка → PR → зелёные проверки → merge. Агент может смержить свой PR сам (`gh pr merge`),
  когда проверки зелёные; если прав не хватает — пусть пришлёт ссылку на PR, вы нажмёте кнопку Merge.
- Прод, VPS и секреты — только у владелицы (ник в игре «Сырь»). Если задаче нужен прод/сервер,
  агент пишет готовые команды, выполнять их будет владелица.

### Карта «теста»: бэкап и восстановление

Снимок рисованной карты «Элизия» лежит в репо: `backups/prod-elysia-map-2026-11-06.json`
(снят с прода 2026-11-06; карта — клиентский контент, не секрет).
Рядом — второй снапшот того же дня после перерисовки локации владельцем
(`backups/prod-elysia-map-2026-11-06-2.json`) и третий — свежий слив перед
лечением (`…-3.json`), плюс леченые версии (`backups/prod-elysia-map-textured-…json`) —
те же альфа/берег, но грунт перезалит текстурным травяным паттерном вместо
плоской заливки grass-1 (причина «пропавших текстур» — старая миграция кисти,
фикс в PR #29; история лечения — в PR #29/#30).

Лечение снимка — скрипт (альфа не трогает, грунт льёт grass-ground,
кромку берега хранит премультиплицированной — как в исходном рисунке):

```bash
python3 scripts/heal-map-texture.py backups/prod-elysia-map-2026-11-06-3.json backups/prod-elysia-map-textured-2026-11-06-3.json
```

Леченая версия `…textured-2026-11-06-3.json` поставлена на прод в тот же день
и сверена обратным сливом (paint совпал байт в байт). Применение леченой
версии к прод-комнате:

```bash
node scripts/set-vps-map.mjs backups/prod-elysia-map-textured-2026-11-06-3.json
```

```bash
npm start           # локальный сервер комнаты (:3780)
npm run map:restore  # залить бэкап в комнату «тест»
npm run map:dump     # снять текущую карту локального сервера в data/fresh-map.json
```

Прод-эндпоинты скрипты не трогают без явного флага `--prod` (см. шапки `scripts/dump-vps-map.mjs`, `scripts/set-local-map.mjs`).
