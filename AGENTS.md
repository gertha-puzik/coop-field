# Инструкции для агентов

Этот файл — общий бриф для Cursor, z.ai и любого другого агента, который пилит coop-field.
Сначала прочитай его целиком, потом код. Не выдумывай вторую архитектуру.

Репозиторий разработки и выкладки: https://github.com/gertha-puzik/coop-field
Ветка, с которой уезжает прод: `main`.

## Что это

Общее поле на 10×6 клеток. Фронт — канвас-симулятор (из abnocw): спрайты, стрела, панель настроек, боевой лог.
Комната — отдельный процесс `server.js`: WebSocket, до 30 котов, сервер решает, кто на какой клетке стоит.

Два контура, их нельзя склеивать в один рантайм:

| Часть | Где код | Куда выкладывается |
| --- | --- | --- |
| Фронт | `src/`, `public/`, Next-конфиг | Vercel, проект `coop-field`, команда `polexka`. Сайт: https://coop-field.vercel.app. Та же статика на VPS: https://abnocw.89-232-184-77.sslip.io , каталог `/opt/coop-field/www` |
| Комната | `server.js`, `deploy/vps/` | VPS `89.232.184.77`, каталог `/opt/coop-field`, systemd `coop-field`. Сокет: `wss://coop.89-232-184-77.sslip.io` |

Vercel не держит долгий WebSocket. Комнату туда не переносить и не «упрощать» до serverless.

## Как запустить локально

```bash
npm install
# терминал 1
npm start
# терминал 2
npm run dev
```

`npm start` — комната на порту 3780. `npm run dev` — Next на http://localhost:3000.
Две вкладки: http://localhost:3000/?room=demo и та же ссылка с другим `?name=`.
Имя по умолчанию можно задать `?name=Сырь`. Чужой сокет для отладки: `?ws=ws://...` — параметр работает только со страниц localhost, в продакшене игнорируется.

Соединение: сервер пингует сокеты раз в 30 с и терминирует умершие (клетка освобождается без close). Клиент при обрыве сам переподключается с backoff (1–2–4–8…30 с, потолок 30) и повторным join; на время обрыва движение и удары по чужим котам заблокированы. Отказы шагов приходят событием `refuse` с кодом (`cell_busy`, `edge`, `cooldown`), текст в `info` — только для статуса.

Проверка комнаты без браузера (сервер уже слушает 3780, либо задай `WS_URL`):

```bash
npm run test:ws
```

## Карта кода

- `src/app/page.tsx` — страница, рисует симулятор.
- `src/components/sim/simulator.tsx` — канвас, клавиши, бой, чат, подключение к комнате.
- `src/components/sim/room-chat.tsx` — панель чата над полем.
- `src/components/sim/settings-panel.tsx` — панель настроек.
- `src/lib/sim/settings.ts` — математика боя, зоны, спрайты, замедление. Углы: 0° вправо, дальше по часовой.
- `src/lib/sim/remote-aim.ts` — чужой прицел по сети.
- `src/lib/net/coop.ts` — клиент комнаты и выбор сокета.
- `src/lib/net/move-book.ts` — предикт своих шагов, откат по отказу, темп достройки чужих котов.
- `server.js` — авторитет комнаты.
- `scripts/test-ws.mjs` — контракт комнаты. Меняешь протокол — обновляй и этот тест.
- `scripts/test-move-queue.mjs` — очередь шагов, гонка за клетку, ответы на залпы (`npm run test:queue`).
- `scripts/replay-har-moves.mjs` — реплей move-таймингов реального боя из HAR против локального сервера.
- `public/sprites/` — спрайты. Имена файлов совпадают с id в `SPRITES`.
- `deploy/vps/package.json` — зависимости только комнаты на VPS (сейчас это `ws`). Корневой `package.json` — фронт и локальная разработка.
- `next.config.ts` — `output: "export"`. Фронт статический. Не переключай на серверный Next без отдельной причины.

## Контракт комнаты

Сообщения — JSON-массив `[событие, данные]`.

Клиент шлёт: `join` (или `first`), `move`, `aim`, `strike`, `sprite`, `chat`.
Сервер шлёт: `you`, `field`, `update cat`, `fight`, `info`, `noplace`, `chat`, `chatlog`.

`strike` с клиента: `{ target, zone, angle }`. Сервер отвечает всей комнате `fight`.
`sprite` меняет скин сразу у всех. `chat` — строка в панели над полем: Enter пишет, Esc возвращает на поле. История новичку приходит как `chatlog`, не больше 40 строк. Пустое сообщение отбрасывается, длиннее 200 символов обрезается, чаще чем раз в 450 мс — отказ.

Движение: кулдаун шага на сервере 80 мс. Ход раньше кулдауна не теряется, а встаёт в очередь глубиной 3 и применяется ровно в момент её снятия; залп длиннее очереди — `refuse` с кодом `cooldown`. Каждый `move` получает ровно один ответ: эхо `update cat` или `refuse`. После отката предикта клиент коротко блокирует новый шаг, чужой кот дорисовывается не быстрее клетки в 60 мс, а при отставании больше 4 клеток ставится сразу в клетку сервера.

Это нельзя ломать молча:

- Сервер — единственный источник клеток. Два кота не стоят в одной клетке, в том числе в момент входа.
- Каждый `move` получает ровно один ответ — эхо или `refuse`. Молчаливое поглощение хода расходится с предиктом клиента, и кот «телепортируется».
- В комнате не больше 30 игроков. Если места нет, сервер шлёт `noplace` и не подселяет в занятую клетку.
- Свободных клеток нет — тот же отказ, а не общая клетка.
- Поле 10 на 6. Координаты клеток в протоколе с 1, не с 0.
- Когти, зубы и нокаут по сети не синхронизируются.
- Локальные манекены живут только пока игрок в комнате один.
- WebSocket принимает origin с localhost, с `https://coop.89-232-184-77.sslip.io`, с `https://abnocw.89-232-184-77.sslip.io` и с `https://coop-field*.vercel.app`. Другой сайт добавляй через переменную `ALLOWED_ORIGINS` на сервисе, не открывай сокет всем origin.
- Тексты интерфейса и сообщения комнаты — по-русски.

Если меняешь событие, поле или отказ — правь вместе `server.js`, `src/lib/net/coop.ts`, `src/lib/net/move-book.ts` и `scripts/test-ws.mjs`, затем прогони `npm run test:ws` и `npm run test:queue`.

## Как пилить фичу

1. Ветка от `main` этого GitHub-репозитория. Прод обновляется только пушем в `main`.
2. Нет прав писать в `main` — открой pull request. Владелец организации `gertha-puzik` мержит его.
3. Сначала воспроизведи текущее поведение локально в двух вкладках: ходьба WASD, прицел, удар клавишей I.
4. Держи сеть и картинку согласованными. Бой на канвасе и удар в комнате — разные куски: локальная математика в `settings.ts`, сетевой удар в `server.js`.
5. После правки комнаты обязательны `npm run test:ws` и `npm run test:queue`. После правки UI проверь две вкладки одной комнаты, а не один скриншот.
6. Не коммить `node_modules`, `.next`, `.vercel`, `.env` и ключи.
7. Зависимость, которая нужна только комнате, добавь в `deploy/vps/package.json` и обнови его lockfile (`npm install --package-lock-only --omit=dev` внутри `deploy/vps`). На VPS стоит свой Node в `/opt/coop-field/.node`, памяти мало, Next туда не ставить.

## Деплой

Пуш в `main` на GitHub запускает Actions. Коммит только в Cursor или в другую копию сам на сайт и сервер не уезжает.

| Workflow | Когда стартует | Что делает |
| --- | --- | --- |
| «Фронтенд на Vercel и VPS» | `src/`, `public/`, Next-конфиг, корневые `package.json` / lockfile, сам workflow | `vercel deploy --prod` в проект `coop-field` и rsync статического `out/` в `/opt/coop-field/www`. Сервис `coop-field` не перезапускается |
| «Сервер комнаты на VPS» | `server.js`, `scripts/`, `deploy/vps/`, сам workflow | rsync пользователем `deploy` и `deploy/vps/apply.sh` |

Правки только `AGENTS.md` и `README.md` выкладку не запускают.

Фронт собирается в Actions (`npm run build` → `out/`). Next на VPS не ставится. Каталог `/opt/coop-field/www` отдельный: rsync комнаты его не трогает (`--delete` там только у `scripts/` в `incoming/scripts/`), rsync фронта с `--delete` чистит только `www/`.

Один раз на сервере, от root (у `deploy` нет sudo на nginx). Vhost комнаты `coop.89-232-184-77.sslip.io` не переписывать: сокет остаётся там.

```bash
sudo mkdir -p /opt/coop-field/www
sudo chown deploy:deploy /opt/coop-field/www
sudo chmod 755 /opt/coop-field /opt/coop-field/www
```

Подключить [`deploy/vps/nginx-www.conf`](deploy/vps/nginx-www.conf) отдельным сайтом nginx. В файле уже `server_name abnocw.89-232-184-77.sslip.io` и корень `/opt/coop-field/www`, слушает только 80. Точный каталог сайтов на сервере в git не лежит.

```bash
sudo nginx -t && sudo systemctl reload nginx
```

HTTPS само не появится. Сертификат комнаты выпущен Let's Encrypt только на `coop.89-232-184-77.sslip.io` и к новому имени не подходит. Если комнатный сертификат выпускал certbot:

```bash
sudo certbot --nginx -d abnocw.89-232-184-77.sslip.io
```

Если certbot нет, тем же способом, которым выпущен сертификат комнаты, выпустить сертификат именно на `abnocw.89-232-184-77.sslip.io` и повесить его на этот server. Чужой сертификат не подставлять.

Пока server нет, `https://abnocw.89-232-184-77.sslip.io` не откроется. Выкладка файлов в `www` при пуше в `main` идёт сама, nginx не перечитывает и комнату не роняет. Клиент с хоста `abnocw` берёт сокет `wss://coop.89-232-184-77.sslip.io` без `?ws=`. Origin этого сайта комнате разрешён вместе со старым origin комнаты.

Секреты репозитория, их нет в git:

- `VERCEL_TOKEN` — токен Vercel с https://vercel.com/account/tokens . Без него фронтенд-workflow падает. Вход через устройство такой токен не выпускает.
- `VPS_SSH_KEY` — ключ пользователя `deploy`. У него есть только `systemctl restart` и `status` сервиса `coop-field`.

Комната перезапускается, только если изменились `server.js` или lockfile зависимостей. Игроки при перезапуске отваливаются. Не рестартуй прод ради проверки текста.

Не подключай этот репозиторий вторым способом в настройках Git у проекта Vercel: получится вторая, параллельная выкладка.

Репозиторий публичный. Секреты из Actions в код и в логи не копировать. Чужой pull request секретов не получает: workflow смотрит только на пуш в `main` и на ручной запуск.
