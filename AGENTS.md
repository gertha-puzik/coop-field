# Инструкции для агентов

Этот файл — общий бриф для Cursor, z.ai и любого другого агента, который пилит coop-field.
Сначала прочитай его целиком, потом код. Не выдумывай вторую архитектуру.

Репозиторий разработки и выкладки: https://github.com/gertha-puzik/coop-field
Ветка, с которой уезжает прод: `main`.

## Что это

Общее поле на 10×6 клеток. Фронт — канвас-симулятор (из abnocw): спрайты, стрела, панель настроек, боевой лог.
Комната — отдельный процесс `server.js`: WebSocket, до 30 котов, сервер решает, кто на какой клетке стоит.

Два контура, их нельзя склеивать в один рантайм:

| Часть | Где код | Куда выкладывается |
| --- | --- | --- |
| Фронт | `src/`, `public/`, Next-конфиг | Vercel, проект `coop-field`, команда `polexka`. Сайт: https://coop-field.vercel.app |
| Комната | `server.js`, `deploy/vps/` | VPS `89.232.184.77`, каталог `/opt/coop-field`, systemd `coop-field`. Сокет: `wss://coop.89-232-184-77.sslip.io` |

Vercel не держит долгий WebSocket. Комнату туда не переносить и не «упрощать» до serverless.

## Как запустить локально

```bash
npm install
# терминал 1
npm start
# терминал 2
npm run dev
```

`npm start` — комната на порту 3780. `npm run dev` — Next на http://localhost:3000.
Две вкладки: http://localhost:3000/?room=demo и та же ссылка с другим `?name=`.
Имя по умолчанию можно задать `?name=Сырь`. Чужой сокет для отладки: `?ws=ws://...`.

Проверка комнаты без браузера (сервер уже слушает 3780, либо задай `WS_URL`):

```bash
npm run test:ws
```

## Карта кода

- `src/app/page.tsx` — страница, рисует симулятор.
- `src/components/sim/simulator.tsx` — канвас, клавиши, бой, чат, подключение к комнате.
- `src/components/sim/room-chat.tsx` — панель чата под полем.
- `src/components/sim/settings-panel.tsx` — панель настроек.
- `src/lib/sim/settings.ts` — математика боя, зоны, спрайты, замедление. Углы: 0° вправо, дальше по часовой.
- `src/lib/sim/remote-aim.ts` — чужой прицел по сети.
- `src/lib/net/coop.ts` — клиент комнаты и выбор сокета.
- `server.js` — авторитет комнаты.
- `scripts/test-ws.mjs` — контракт комнаты. Меняешь протокол — обновляй и этот тест.
- `public/sprites/` — спрайты. Имена файлов совпадают с id в `SPRITES`.
- `legacy-grid/` — старый клиент. В прод не входит, не чини его «заодно».
- `deploy/vps/package.json` — зависимости только комнаты на VPS (сейчас это `ws`). Корневой `package.json` — фронт и локальная разработка.
- `next.config.ts` — `output: "export"`. Фронт статический. Не переключай на серверный Next без отдельной причины.

## Контракт комнаты

Сообщения — JSON-массив `[событие, данные]`.

Клиент шлёт: `join` (или `first`), `move`, `aim`, `strike`, `sprite`, `chat`.
Сервер шлёт: `you`, `field`, `update cat`, `fight`, `info`, `noplace`, `chat`, `chatlog`.

`strike` с клиента: `{ target, zone, angle }`. Сервер отвечает всей комнате `fight`.
`sprite` меняет скин сразу у всех. `chat` — строка в панели под полем: Enter пишет, Esc возвращает на поле. История новичку приходит как `chatlog`, не больше 40 строк. Пустое сообщение отбрасывается, длиннее 200 символов обрезается, чаще чем раз в 450 мс — отказ.

Это нельзя ломать молча:

- Сервер — единственный источник клеток. Два кота не стоят в одной клетке, в том числе в момент входа.
- В комнате не больше 30 игроков. Если места нет, сервер шлёт `noplace` и не подселяет в занятую клетку.
- Свободных клеток нет — тот же отказ, а не общая клетка.
- Поле 10 на 6. Координаты клеток в протоколе с 1, не с 0.
- Когти, зубы и нокаут по сети не синхронизируются.
- Локальные манекены живут только пока игрок в комнате один.
- WebSocket принимает origin с localhost, с `https://coop.89-232-184-77.sslip.io` и с `https://coop-field*.vercel.app`. Новый сайт добавляй через переменную `ALLOWED_ORIGINS` на сервисе, не открывай сокет всем origin.
- Тексты интерфейса и сообщения комнаты — по-русски.

Если меняешь событие, поле или отказ — правь вместе `server.js`, `src/lib/net/coop.ts` и `scripts/test-ws.mjs`, затем прогони `npm run test:ws`.

## Как пилить фичу

1. Ветка от `main` этого GitHub-репозитория. Прод обновляется только пушем в `main`.
2. Нет прав писать в `main` — открой pull request. Владелец организации `gertha-puzik` мержит его.
3. Сначала воспроизведи текущее поведение локально в двух вкладках: ходьба WASD, прицел, удар клавишей I.
4. Держи сеть и картинку согласованными. Бой на канвасе и удар в комнате — разные куски: локальная математика в `settings.ts`, сетевой удар в `server.js`.
5. После правки комнаты обязателен `npm run test:ws`. После правки UI проверь две вкладки одной комнаты, а не один скриншот.
6. Не коммить `node_modules`, `.next`, `.vercel`, `.env` и ключи.
7. Зависимость, которая нужна только комнате, добавь в `deploy/vps/package.json` и обнови его lockfile (`npm install --package-lock-only --omit=dev` внутри `deploy/vps`). На VPS стоит свой Node в `/opt/coop-field/.node`, памяти мало, Next туда не ставить.

## Деплой

Пуш в `main` на GitHub запускает Actions. Коммит только в Cursor или в другую копию сам на сайт и сервер не уезжает.

| Workflow | Когда стартует | Что делает |
| --- | --- | --- |
| «Фронтенд на Vercel» | `src/`, `public/`, Next-конфиг, корневые `package.json` / lockfile, сам workflow | `vercel deploy --prod` в проект `coop-field` |
| «Сервер комнаты на VPS» | `server.js`, `scripts/`, `deploy/vps/`, сам workflow | rsync пользователем `deploy` и `deploy/vps/apply.sh` |

Правки только `AGENTS.md` и `README.md` выкладку не запускают.

Секреты репозитория, их нет в git:

- `VERCEL_TOKEN` — токен Vercel с https://vercel.com/account/tokens . Без него фронтенд-workflow падает. Вход через устройство такой токен не выпускает.
- `VPS_SSH_KEY` — ключ пользователя `deploy`. У него есть только `systemctl restart` и `status` сервиса `coop-field`.

Комната перезапускается, только если изменились `server.js` или lockfile зависимостей. Игроки при перезапуске отваливаются. Не рестартуй прод ради проверки текста.

Не подключай этот репозиторий вторым способом в настройках Git у проекта Vercel: получится вторая, параллельная выкладка.

Репозиторий публичный. Секреты из Actions в код и в логи не копировать. Чужой pull request секретов не получает: workflow смотрит только на пуш в `main` и на ручной запуск.
