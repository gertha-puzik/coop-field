## P0

### A1 — PNG-бомба рисунка локации

- **Приоритет:** P0
- **Статус:** `confirmed-open` на `2a018fa`. Исправление вынесено в `cursor/png-inflate-cap-f2d4` и в этот PR не входит.
- **Доказательство:** `decodePaintPng` в `server/world.js` вызывал `zlib.inflateSync` без `maxOutputLength`. Проверка длины сырого кадра стояла после распаковки. Сюда попадает `sanitizeTestMap` в `server/testmap.js`: base64 рисунка режется на 3 500 000 символов, а транспортный потолок — `MAX_PAYLOAD` в `server/config.js` (4 МиБ). Легальный рисунок — `cols×100` на `rows×150` внутри `TEST_MAP_LIMITS` (`server/protocol.js`). Чужой IHDR с крошечным, но сильно сжимаемым IDAT раздувал вывод до проверки размера.
- **Игроку:** любой участник комнаты `test` шлёт `setmap`. Один кадр может уронить процесс комнаты для всех, включая пивные гроты на том же Node.
- **Что сделано рядом:** до `inflateSync` ширина и высота обязаны быть сеткой локации; `maxOutputLength` равен честному RGBA этого кадра, но не больше максимального легального кадра 60×40 плюс 64 байта. Счастливый путь сохранения карты не менялся. Негативный тест: раздутый IDAT и огромный IHDR дают `null`, процесс остаётся жив (`scripts/test-server-modules.mjs`).
- **Приёмка фикса:** `npm run test:server-modules`, `npm run typecheck`, `npm run arch:check`. `server/world.js` остаётся ≤800 строк (779).
- **Зависимости:** нет. Не ждать решения по D4: лимит нужен и при открытом редакторе.
- **Решение владелицы:** не требуется для самого лимита.

### A4 — токен сессии в кадре `whoami`

- **Приоритет:** P0
- **Статус:** `confirmed-open` на `2a018fa`. Исправление вынесено в `cursor/whoami-token-scope-f2d4`.
- **Доказательство:** `whoamiBody` в `server/auth.js` клал `ws.sessionToken` в кадр при любом `hostClass`. `handleAuthFrame` на действии `hello` делал `bindToken` из `payload.token` без `originOk`. HTTP-тела на elyria токен уже не отдают (`handleAuthHttp`). Тест `scripts/test-auth.mjs` прямо закреплял старое поведение: «WS-кадр на elyria выдаёт токен whoami (матрица — про HTTP-тела)». Клиент токен из кадра не хранит (`applyWhoami` в `src/lib/net/auth.ts`), но страница может прочитать кадр и обойти HttpOnly.
- **Игроку:** украденный кадр или страница на том же хосте получает строку сессии, которой кука наружу не отдаётся. `hello` с токеном без своего Origin поднимал чужую сессию на сокете.
- **Что сделано рядом:** `token` в `whoami` только при `hostClass === "local"`. На public/elyria `hello` с непустым `payload.token` требует `originOk`. Local-dev и скрипты без Origin не сломаны: `ws register: token` в `test:auth` остаётся зелёным. Матрица записана в `AGENTS.md`, `docs/PLATFORM-ARCHITECTURE.md`, `docs/PRIVACY-DATA.md`, `docs/ARCHITECTURE.md`, `docs/AI-CONTEXT.md`.
- **Приёмка фикса:** `npm run test:auth`, `npm run test:cross-origin`, `npm run check:protocol`, `npm run test:server-modules`, `npm run typecheck`, `npm run arch:check`.
- **Зависимости:** не ослабляет cookie-only на elyria. `AUTH_LEGACY_TOKEN` этим фиксом не включается и не выключается.
- **Решение владелицы:** не требуется. Контракт local сохранён.

### E2 — карта `hits` в auth растёт без потолка

- **Приоритет:** P0 (память процесса; не секрет и не RCE)
- **Статус:** `confirmed-open` на `2a018fa`. Исправление вынесено в `cursor/auth-hits-cap-f2d4`.
- **Доказательство:** `rate` в `server/auth.js` пишет каждый не-loopback IP в `const hits = new Map()` и не вызывает `delete`. Просроченные метки вычищаются только когда тот же IP приходит снова. Рядом `noteLoginFail` уже имеет `LOGIN_FAIL_MAP_MAX = 4096` и чистит протухшие ключи. Loopback по-прежнему не лимитируется (`isLoopback`).
- **Игроку:** поток регистраций и логинов с разных адресов раздувает память единственного процесса комнаты. На инстансе с `MemoryMax=256M` (`deploy/vps/coop-field.service`) это ближе к падению, чем к «просто утечке в таблице».
- **Что сделано рядом:** при новом IP и размере ≥4096 сначала prune окна в 1 час, затем выселение самого старого бакета. Уже известный IP не выселяется ради своей же попытки. Тест: 10 000 адресов `203.*` не поднимают `hitsMapSize()` выше `HITS_MAP_MAX`; loopback карту не пишет.
- **Приёмка фикса:** `npm run test:server-modules`, `npm run test:auth`, `npm run typecheck`, `npm run arch:check`.
- **Зависимости:** нет. Это не замена per-login замка.
- **Решение владелицы:** не требуется. Потолок 4096 совпадает с `LOGIN_FAIL_MAP_MAX`. Жёсткое выселение свежих бакетов — осознанный шаг сверх `loginFails`: иначе 10 000 свежих IP всё равно росли бы.

### A3 — нет темпа на `block`, `space`, `atmo`, dummy/rab

- **Приоритет:** P1
- **Статус:** `confirmed-open`
- **Доказательство:** `onMessage` в `server/net.js` отсекает только размер (`FRAME_LIMIT` в `server/config.js`, 64 КиБ, кроме `setmap`). Дальше:
  - есть темп: `move` (`movement.js`, `MOVE_COOLDOWN_MS`), `aim` (`combat.js`, `AIM_MIN_GAP_MS`), `strike` (`STRIKE_COOLDOWN_MS`), `chat` (`sanitize.js`, `CHAT_COOLDOWN_MS`), `freemove` (рассылка раз в `FREE_MOVE_GAP_MS`, сама точка пишется чаще), `jump`, `setMap` (`SETMAP_MIN_GAP_MS`), `roomsInfo` (`ROOMS_MIN_GAP_MS`);
  - темпа нет: `block` и `space` в `server/room.js`, `atmo` и `atmoset` в `server/atmo.js`, `dummyToggle` / `dummyMove` / `dummyGrab` / `dummyDrop` / `rabToggle` / `rabHit` в `server/dummy-rab.js`.
  Честный клиент шлёт `block`/`space` на нажатие и отпускание (`use-keyboard.ts`), `atmo` — с кнопки (`simulator.tsx`), `dummyMove` — на движение указателя (`pointer-tools.ts`). Злой сокет может слать эти кадры пачкой: каждый уходит `broadcast` в комнату.
- **Игроку:** в общей комнате чужой клиент забивает канал соседям кадрами блока, погоды или перетаскивания манекена. Это не OOM само по себе и не кража сессии.
- **Предлагаемый фикс:** не переписывать диспетчер. Отдельные зазоры по образцу уже существующих: `block`/`space`/`atmo`/`atmoset`/`rab*` — короткий зазор на сокет (десятки миллисекунд, эхо состояния не терять на настоящем keyup); `dummyMove` — зазор как у `freemove` (50 мс на рассылку, локальную точку можно принимать чаще). Молчаливый drop, без нового имени события.
- **Приёмка:** легитимные нажатия K и пробела доходят; перетаскивание манекена не рвётся; пачка из тысяч кадров за секунду не размножается в комнату 1:1. Регрессия — `npm run test:ws` (когда его включат, см. F1) плюс узкий самоподнятый скрипт.
- **Тесты сейчас:** контракт этих событий в `scripts/test-ws.mjs` есть как поведение, не как антифлуд.
- **Зависимости:** не смешивать с A1. Не резать `setmap` ещё раз — там уже 10 с.
- **Почему не сделано сейчас:** это несколько горячих путей, и `dummyMove` завязан на частоту указателя. Один общий бакет в `onMessage` менял бы ощущение перетаскивания. Это уже не «дырка в одну строку».

### A5 — заголовки и TLS гротов в nginx

- **Приоритет:** P1
- **Статус:** `needs-owner`
- **Доказательство:** `deploy/vps/nginx-www.conf` слушает только `80`, `server_name abnocw.89-232-184-77.sslip.io`. Единственный `add_header` в дереве vhost — `Cache-Control` у `/_next/static/`. Комментарий в том же файле: сертификата на это имя в репозитории нет, фрагмент применяет root вручную, пользователь `deploy` sudo на nginx не имеет. - **Игроку:** страница гротов по HTTP без защитных заголовков проще встраивается чужим сайтом и не обещает браузеру HTTPS. Это не чинится мержем в `main`: nginx на VPS не перечитывает репозиторий сам.
- **Предлагаемый фикс:** владелица выпускает сертификат на публичное имя гротов и кладёт versioned snippet (заголовки + `listen 443 ssl`) в репозиторий, затем root один раз подключает include и делает reload. Пока сертификата нет, сниппет в git легко принять за «прод уже починен».
- **Приёмка:** `curl -sI` на боевое имя показывает HTTPS и заголовки. Репозиторный файл совпадает с тем, что реально подключён. Агент прод не рестартует.
- **Тесты:** репозиторных нет; проверка только на VPS глазами владелицы.
- **Зависимости:** имя сертификата, DNS, root. Не связано с комнатой `coop-field.service`.
- **Решение владелицы:** да. В этом проходе файл не добавлялся.

### A6 — нет удаления аккаунта; день рождения в публичной карточке

- **Статус:** `confirmed-open`
- **Доказательство:** маршрута удаления нет. `docs/PRIVACY-DATA.md` §1 прямо пишет: no account-deletion route; забывается только позиция кота (`forgetCat`). В `server/accounts.js` экспорт — `createAccount` / `promoteToAdmin`, не delete. Таблица §3 в `docs/PRIVACY-DATA.md` поле `birthday` не перечисляет: документ отстал от кода, а не наоборот.
- **Игроку:** дату рождения, один раз сохранённую в профиле, видит любой, кто открыл каталог Элизии. Удалить аккаунт и сессии самому нельзя: строка живёт, пока кто-то не сотрёт `accounts.json` руками.
- **Предлагаемый фикс:** не в этом проходе. Отдельная волна: подтверждённое удаление своей учётки (cookie + CSRF + повтор), гашение сессий, личных окрасов и книги позиций; день рождения либо убрать из `publicProfile`, либо оставить только владельцу, либо показывать не дату, а признак «указан». Юридическую квалификацию (152-ФЗ) этот фикс не заменяет.
- **Приёмка:** `GET /profiles` и `GET /profiles/:id` не содержат полную дату, если владелица так решит; `GET /profiles/me` по-прежнему показывает её владельцу. - **Зависимости:** решение владелицы, показывать ли дату всем. Удаление трогает сессии, спрайты и книгу котов — это больше одного файла.

## Ложные следы

Их не надо заводить заново. Проверено по коду `2a018fa`, не по старым отчётам.

- **«Пароль редактора 1946 всё ещё в сервере и открывает карту».** `stale-or-wrong`. В `server/` строки `1946` нет. `setMap` пароль игнорирует. Живы комментарий юнита и тестовый `MAP_PASS`. См. A7.
- **«Ландмарки разъехались, гейт красный».** Для 18 пар, которые `check-doc-landmarks.mjs` реально сверяет, гейт зелёный. Врут другие, неподнадзорные серверные числа. См. F2.
- **«Нет никакого темпа кадров».** Слишком широко. Темп есть у шага, прицела, удара, чата, рассылки `freemove`, прыжка, `setmap` и `rooms`. Дыра — именованный список A3.
- **«Нет CSRF, пароли не scrypt, нет лимита сокетов с одного IP, нет host-изоляции, нет sanitize, нет гейта протокола, файлы не режутся по 800».** На `2a018fa` это уже есть, если старый аудит всё ещё так пишет:
  - CSRF: `csrfDecision` / `csrfStrictFor` в `server/config.js`, вызов из `handleAuthHttp` и `handleProfilesHttp`;
  - пароль: `hashPassword` в `server/accounts.js` (`scrypt`, `timingSafeEqual`);
  - сокеты: `WS_MAX_PER_IP` в `server/config.js`, учёт в `startServer` (`server/net.js`);
  - хосты: `hostClassOf` в `server/config.js`;
  - чат: `sanitize.js`;
  - протокол: `npm run check:protocol` и `npm run test:protocol-parity`;
  - размер файлов: `scripts/check-architecture.mjs`, лимит 800, allowlist только у наследия.
- **«День рождения в профиль не попадает».** Наоборот: в публичную карточку попадает (`publicProfile`). В `whoami` — нет. См. A6.
- **«ADMIN_PASS по-прежнему аварийный ключ setmap».** Так написано в старых абзацах `docs/PRODUCT-ROADMAP.md`. Код `setMap` ключ не читает. Дорожная карта здесь отстала; правку карты этого PR не делали, чтобы не смешивать учёт с пересказом истории.
