- **A1 — изоляция маркеры-ноль:** env-свёртка хостов/маршрутов Элизии и боевых миров в
  мёртвых ветках (инлайн-канон site.ts, arch-правило isolatedImports), гейт
  `npm run check:variants` в preview-build после сборки до упаковки артефакта;
  **A2/D4** — paths-фильтр CI теперь требует ревью правок всех workflows и deploy-скриптов.
- **S1–S5 (аудит Z.AI):** роль admin — только одноразовый CLI `scripts/make-admin.mjs`

## Коротко, простыми словами

Сейчас Coop Field — это **одна страница** с экраном входа и общим canvas-полем.
Игрок пишет имя, выбирает скин и «скрытые параметры» (скорость стрелы, урон,
броня), заходит в комнату. Комнат четыре: три «Пивных грота» (клеточное поле
10×6, бой, манекен, мишень РАБ) и «Элизия Эйдес» (рисованная локация, мирная
ходьба, редактор карты, сутки и погода).

**Аккаунтов нет.** Имя — это просто подпись в комнате: любой может назваться
«Сырь». Настройки живут в браузере этого компьютера. Позиция кота в Элизии
запоминается на сервере по этому имени. Пароль редактора карты — отдельный
секрет сервера, не вход в игру.

**Отдельного режима «активный бой» нет** — гроты и есть бой; «голодные игры» — каркас
без правил (страница-заглушка). Страницы режимов живут на своих адресах: `/combat/`
(гроты), `/game/` (закрытая локация сессией), `/hunger/` (каркас), плюс `/players/`
и `/admin/` на Элизии. Preview-окружения для пул-реквестов есть, двухсайтовые
(`pr-<N>.abnocw.phainonsmilk.ru` + `pr-<N>.elysiae.phainonsmilk.ru`), см.
[PREVIEW-ENVIRONMENTS.md](PREVIEW-ENVIRONMENTS.md); мерж в `main` по-прежнему является
деплоем прода — но теперь через CI и два rsync, а не мгновенно.

Встроенного ИИ-помощника **не будет и не нужно**: справочник Герты + `AGENTS.md`
+ метаданные механик — это и есть интерфейс для Cursor. Чат без настоящей
языковой модели — фиктивная кнопка, её делать нельзя.

### Настройки / «админка»

Панель `settings-panel.tsx` (1240 строк, 30 пропсов). Ниже — состояние на ветке платформы;
список честно перерисован, потому что фейк-пароль вкладок **снят волной (P3)**:
вкладки `admin:true` теперь рендерятся только при `role==='admin'` из серверного `whoami`
(истина — на сервере), серверный каталог настроек переехал в админ-дашборд `/admin`
(реестр 5 ключей, apply/reset/restore/export/import); клиентский import/export JSON
остался личным (только в этом браузере).

- вкладка «Общий» — всем: манекен/РАБ (не в Элизии), поле, персонаж, атмосфера;
- вкладки Стрела / Замедление / Удары — за ролью (раньше: за «паролем», любой непустой
  ввод; сервер проверял только setmap с `ADMIN_PASS`);
- конфиг: экспорт / импорт JSON / «сбросить всё» — **только в этом браузере**,
  сервер об этом не знает;
- опасные действия без второго подтверждения (сброс сразу);
- нет каталога «что применится сейчас / в новой комнате / после рестарта»;
- нет серверных конфигов по режимам, истории, сравнения.

## 2. Что отсутствует (по аудиту на f75768f; пункты 1–4 закрыты платформенной волной, см. баннер вверху)

1. **Аккаунт** (логин+пароль), отдельно от **профиля** и отдельно от **персонажа**.
2. **Сессия**: вход, выход, сервер знает, кто в сокете, и не верит клиентскому `login`.
3. **Закрытая Элизия**: гость не входит, даже прямым WebSocket.
4. **Регистрация** на странице Элизии (гроты при этом остаются гостевыми).
5. **Страницы режимов** (есть на ветке: `/combat/`, `/elision/`, `/hunger/`); отдельные
   комнаты «активный бой» / «голодные игры» **не заводились и не нужны**: гроты и есть бой,
   код `combat` алиасится в `grot-1`, у hunger правил нет — только каркас.
6. **Админка для не-программиста**: русские описания, обычное/расширенное,
   подтверждение опасного, «что будет после сохранения», сервер = правда.
7. **Каталог безопасных параметров** (не инварианты движка) с синхронизацией
   UI ↔ клиент ↔ сервер.
8. **Конфиги по режимам** на сервере: сохранение, сброс, import/export, backup,
   история, сравнение.
9. **Справочник Герты** из типизированных метаданных реальных файлов.
10. **Preview PR**: `https://<ветка>.abnocw.phainonsmilk.ru`, front+WS одной ветки,
    изоляция от прода, один комментарий, без форков на VPS.

## 3. Какие пожелания уже частично покрыты

См. таблицу в §9. Коротко:

- «Персонажи» в карусели — это **группы скинов**, не сущности аккаунта (на платформенной
  ветке у Элизии есть настоящий аккаунт — но персонаж всё равно один выбранный скин).
- «Сохранение кота» — позиция по **имени** + настройки в **браузере**, не профиль.
- «Админка» — панель настроек движка; пароль вкладок был фиктивным (на платформенной
  ветке снят: вкладки по роли сессии, серверные настройки — в `/admin`); карта — да,
  серверная, но одним секретом `ADMIN_PASS`.
- «Режимы» — два формата поля (`grid` / `test`), не три продукта.
- «Конфиг» — JSON в браузере, не серверные пресеты режима (на платформенной ветке
  серверные пресеты появились — но только 5 ключей реестра, остальное по-прежнему личное).
- «Справочник» — `AGENTS.md` / `ARCHITECTURE.md` / `AI-CONTEXT.md` для агентов,
  не карточки механик внутри игры на русском.
- «Деплой» — прод-пайплайн зрелый; preview нужно **встроить в него**, а не
  ставить рядом Docker.

## 5. Архитектурные ограничения (нельзя ломать)

1. Фронт — статический экспорт. Бэкенд аккаунтов — **только room-server**.
2. Клиент и сервер не шарят код. Константы и имена событий — зеркала + CI.
3. Новый файл ≤ 800 строк. Allowlist arch:check **не расширять**.
4. God-файлы (`simulator.tsx`, `settings-panel.tsx`, `settings.ts`, `test-field.ts`)
   не растить «мимоходом». Новое — соседние модули.
5. Инварианты комнаты: одна клетка — один кот; каждый шаг — один ответ;
   координаты 1-based / 0-based / fx-fy не смешивать.
6. Секреты только из env. Legacy `ADMIN_PASS` в коде — переходное исключение,
   не образец.
7. Прод и VPS — только владелица. Агент пишет команды, не заходит на прод.
8. Мерж в `main` = выкладка. Ветки + PR.
9. `next-env.d.ts` флип от `next dev` в коммит не класть. `agentRules: false`.
10. Прод-сокет скрипты не трогают без `--prod`.

| SQLite «на всякий случай» | Новая зависимость и бэкап-схема ради десятков игроков | JSON + atomic write, как карта; SQLite только если упрёмся в порчу файла от гонок |

## 7. Рекомендуемая архитектура (сжато)

Полные схемы — в [PLATFORM-ARCHITECTURE.md](PLATFORM-ARCHITECTURE.md). Здесь — выбор.

1. **Auth на существующем Node-сервере.** JSON в `DATA_DIR`
   (`accounts.json`, `sessions.json`). Пароль: `scrypt` из `node:crypto`
   (без npm-пакета). Сессия: непрозрачный токен, сервер — source of truth.
   Браузер: httpOnly cookie на HTTP-ручке комнаты. (Реализовано волной: cookie
   HttpOnly — единственный транспорт на Элизии; `?t=` остался env-тумблером
   `AUTH_LEGACY_TOKEN` для перехода и работающим путём на local — там на нём
   стоят тесты.) Не JWT в localStorage как правда.
   Внешний Google/GitHub — не в этой волне.
2. **Три сущности:** аккаунт (вход) ≠ профиль (как меня видят) ≠ персонаж
   (скин, рост, СП). У аккаунта несколько персонажей; в комнату входит один.
3. **Роли на сервере:** `guest` (нет сессии) / `registered` / `admin`.
   Модератор — только если владелицы скажут, зачем (сейчас модель управления —
   владелица с `ADMIN_PASS` на карту). `ADMIN_PASS` остаётся аварийным ключом
   `setmap`, не «логином Герты».
4. **Режимы:** Элизия закрыта (`test`, формат как сейчас). Гроты открыты и
   живут на `/combat/` — это и есть abnocw, отдельной подписи «активный бой» нет.
   Голодные игры — страница «в разработке», без выдуманных правил раунда.
   Регистрация живёт на `/game/`, гостей гротов не блокирует.
5. **Страницы static export:** `/` меню Wanderpaws, `/combat/` гроты,
   `/game/` Элизия, `/hunger/` заглушка. Игровые страницы — один
   `Simulator` с конфигом режима. Code-split естественный (маршрут Next).
6. **Админка** — вкладки той же панели + серверный каталог безопасных полей.
7. **Справочник Герты** — типизированные метаданные в репо, UI на русском.
8. **ИИ:** не строить. Cursor читает этот справочник и `AGENTS.md`.
9. **Preview (решение владелицы):** тот же VPS, каталог
   `/opt/coop-field-preview/<slug>/` + отдельный порт + свои `data/` + nginx
   `*.abnocw.phainonsmilk.ru`. Сборка из SHA коммита. Прод-пайплайн не менять.
   DNS wildcard уже в зоне. Агент на VPS не заходит; остаток шагов — у Сырь.

## 10. ИИ-помощник — явное решение

**Встроенную языковую модель не строим.** Причины: нет бэкенда под LLM на
static export, VPS комнаты не для этого, «чат без модели» — мёртвая кнопка
(запрещена задачей).

Интерфейс для Cursor уже есть и его надо **улучшать как данные**, а не как чат:

- `AGENTS.md` — куда идти и контракт провода;
- `docs/ARCHITECTURE.md` — слои и зеркала;
- `docs/AI-CONTEXT.md` — однофайловое досье для чатов без файловой системы;
- справочник Герты (фаза 5) — те же факты в виде карточек внутри админки,
  чтобы не-программист и агент смотрели одно.

## 11. Открытые вопросы (только то, что код не решает)

Агенту не блокировать работу этими вопросами, кроме правил Голодных игр
(их не выдумывать — только основа).

### 1. Кто может быть админом в новой модели?

> **Решено платформенной волной (P1–P2):** вариант A — env `BOOTSTRAP_ADMIN` со списком
> логинов (через запятую); каждый логин из списка при своей первой регистрации получает
> роль `admin`, прочие — `registered`. `ADMIN_PASS` остался аварийным ключом `setmap`.
> Настройки ниже — история вопроса.

- **Проблема.** Сейчас карта Элизии открывается секретом `ADMIN_PASS`.
  Роли пользователей нет. Нужно не смешать «владелица сервера» и «игрок с
  расширенными вкладками».
- **Варианты.** (A) Первый зарегистрированный с логином из env
  `BOOTSTRAP_ADMIN` становится `admin`, остальные — `registered`. (B) Админ
  только тот, кто знает `ADMIN_PASS` (как сейчас), роли в аккаунте не заводим.
  (C) Явный список логинов в env.
- **Рекомендация.** A + сохранить `ADMIN_PASS` как аварийный ключ `setmap`.
- **Вопрос.** Ок ли, что Сырь при первом запуске регистрируется логином из
  env и становится админом, а пароль карты остаётся отдельным «ключом от
  редактора»?

### 2. Правила Голодных игр

- **Проблема.** В коде нет ни карты, ни победы, ни лута, ни выбывания.
- **Варианты.** (A) Только комната-песочница с пометкой «правила появятся».
  (B) Владелицы пишут правила, агент кодирует следующей волной. (C) Списать
  с внешней игры — риск «не та игра».
- **Рекомендация.** A в этой волне.
- **Вопрос.** Какие 3–5 правил должны быть первыми, когда дойдём до правил
  (выбывание? одна жизнь? безопасная зона?) — **не придумывать за вас**.

### 3. Нужен ли модератор?

- **Проблема.** В пожелании есть роль moderator. В текущей игре модерирует
  владелица (кик = рестарт/игнор, чат без бана).
- **Варианты.** (A) Не вводить до появления бана/кика. (B) Ввести пустую роль.
  (C) Сразу кик из комнаты.
- **Рекомендация.** A — пустая роль хуже, чем её нет.
- **Вопрос.** Нужен ли кик из комнаты в этой волне, или достаточно закрытой
  Элизии?

Эти три вопроса **не останавливают** фазы 2–6: закрываем Элизию ролью
`registered`, админа сидим через env, голодные — каркас, модератора не
заводим.
