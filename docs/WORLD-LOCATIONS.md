# Локации мира

Первая зона: **Средиземье**, ID зоны **1**. Сейчас доступны две отдельные карты:

| ID | Локация | Комната | Файл в DATA_DIR |
| --- | --- | --- | --- |
| 1 | Долина | `test` | `test-map.json` — существующая карта сохранена |
| 2 | Редколесье | `test-loc-2` | `location-2.json` — новая площадка 10×10 |
| 3+ | созданные в редакторе | `test-loc-<id>` | `location-<id>.json` — стартовое поле 10×10 |

Реестр ID живёт в `locations-index.json` (+ обнаружение `location-N.json`).
Следующий ID = max(известных) + 1. Создание — кнопка в редакторе «Мир» или
`POST /locations` (admin; алиас `POST /admin/locations`). Редколесье и новые карты создаются только при
отсутствии файла. Долина не заменяется шаблоном новой карты. Каталог соседней
локации не должен блокировать вход в здоровую первую, даже если соседний файл
повреждён; повреждённый файл не перезаписывается.

## Как настроить проход

1. В редакторе откройте **Зоны → Область перехода**.
2. Выберите целевую локацию по имени и ID, ширину, длину и направление прохода.
3. Клик по карте ставит прямоугольную область в свободных координатах; ПКМ удаляет
   область под курсором. Список переходов также содержит кнопку удаления.
4. Нажмите **Сохранить локацию**. Переходы не создаются автоматически: первый проход
   из Долины и обратный проход в Редколесье размещает автор карты.
5. Если между двумя картами несколько пар проходов, задайте каждой паре один
   уникальный **ключ связи** (латиница, цифры, дефис/подчёркивание, до 32 символов).
   Ключи нужны, чтобы выходы не перепутались.

В **Мир** находятся название с неизменным ID, переключение локаций и создание
новой локации (следующий свободный ID, стартовая карта 10×10). Кнопка
«Задать название локации» меняет черновик; название публикуется обычной кнопкой
сохранения. При переключении с несохранёнными изменениями есть подтверждение
их отмены. Переключение редактора не требует игрового прохода.

История, отмена/повтор, сохранение и ZIP-архив содержат название/ID, зону и области
переходов вместе с остальной картой. Архивы имеют ID в имени; импорт не меняет ID
текущей локации. Полная очистка также удаляет проходы и поддерживает отмену.

## Что видит игрок

В мирном режиме внутри области появляется «Путь в …», ниже — название зоны.
`E` или кнопка перехода запускает короткий подход, затемнение и полноэкранный
Wanderpaws. Управление на время перехода отключено. Прогресс показывает получение
карты и готовность изображения/рендера; счётчик ожидания отдельный.

По умолчанию загрузочный экран остаётся на **10 секунд**. Если карта готова раньше,
повторное `E` или «Продолжить сейчас» ускоряет вход. Неготовая карта не открывается
по клавише или истечению таймера. Обрыв до получения карты отменяет переход,
после получения — ждёт восстановления связи. Длинная загрузка предлагает
перезагрузить локацию.

Место прибытия выбирает сервер возле обратной области с подходящим ключом, вне её
триггера и препятствий (занятость мирного кота — по лапам `fx/fy`, не по устаревшей
боевой клетке). Если обратного прохода нет — стартовая точка; если кольцо у выхода
забито — запасной спавн локации вне триггера. Несколько неоднозначных обратных
проходов или полное отсутствие места дают понятный отказ; игрок остаётся на карте.

Над погодой показано **СРЕДИЗЕМЬЕ — Долина / Редколесье**. Чат и игроки разделены
по локациям. URL, переподключение и новый вход сохраняют выбранную локацию;
явная ссылка на другую комнату имеет приоритет. Счётчик мира в меню суммирует обе.

## Схема и границы

- `TestMap.place`: `{id, name, zoneId, zoneName}`. Старые карты без метаданных
  остаются Долиной; существующие рисунок, высоты и объекты не переезжают.
- `TestMap.passages`: до 128 `{id,x,y,w,h,targetId,link,direction}`. Координаты —
  доли клеток земли, размеры допускают десятичные значения. ID областей уникальны.
- `join {passageId}` проверяет авторизацию, мирный режим и нахождение в сохранённой
  области. Назначение и позиция прибытия не принимаются от клиента.
- `join {room, resume?}`: обычный вход; `resume:true` на первом входе без явного
  room возвращает последнюю локацию персонажа. Неисправная соседняя карта даёт
  безопасное возвращение в Долину. Все локации требуют аккаунт, редактор — admin.
- `field.locations` — исходный каталог; серверное событие `locations` обновляет
  переименования в других комнатах без пересылки их карт.
- Сервер хранит независимые геометрические снимки. Legacy-функции world.js читают
  live bindings только внутри синхронного `withTestLocation`; `finally` восстанавливает
  контекст, в том числе при вложенных вызовах и исключениях. Нельзя держать этот
  контекст через `await`. Очередь движений, spawn, join и FIELD выбирают свой контекст.
- Старый ключ позиции Долины сохранён; другие карты имеют суффикс location ID.
  `lastLocationId` в базовой записи помнит последнюю карту. Наследуется существующее
  ограничение книги позиций по имени персонажа; смены ID аккаунтов здесь нет.
- Атомарные записи, откат при ошибке и восемь резервных копий работают отдельно для
  каждой карты. Клиент не переносит поздно декодированный рисунок в черновик другой.

Проверки: `npm run test:locations`, `npm run test:editor-save` и обязательные гейты
AGENTS.md. Полный браузерный маршрут дополнительно проверяет создание/сохранение
областей, ручное ускорение, десятисекундное ожидание, обратное появление, смену
редактора, возобновление комнаты и восстановление после обрыва.
