# Профиль: шапка «как в Твиттере», генерация/рисование шапки, лента действий, новая вёрстка

Дата: 2026-11-14. Сайт: Элизии (`NEXT_PUBLIC_SITE=elyria`), страница `/players?id=`.

Макет владелицы: [2026-11-14-profile-mockup.webp](2026-11-14-profile-mockup.webp) — эталон
вёрстки (рамки карточек, высота шапки, наезд аватара). Блоки «Достижения» и боевые
цифры на нём — вне этой задачи (см. «Не цели»).

## Зачем

Владелица хочет профиль, похожий на присланный макет (WANDERPAWS-стиль: широкая
пиксельная ночная шапка, аватар поверх неё, карточки в две колонки). Игрок должен
сам оформлять шапку так же легко, как в Твиттере, а у тех, кто шапку не ставил,
профиль не должен выглядеть пустым. Лента «Последние действия» делает профиль
живым — видно, чем игрок занят.

## Цели

1. **Кадрирование шапки.** Любая картинка → окно с рамкой 3:1, перетаскивание и
   зум → браузер вырезает 1200×400 и грузит через существующий `POST /cfg/banners/mine`.
2. **Сгенерированная шапка**, если своей нет: пиксельный ночной пейзаж, детерминированный
   от `accountId` (у каждого свой, не меняется между заходами). Только клиент, ничего не хранится.
3. **Нарисовать шапку**: пиксельный редактор 120×40 клеток (масштаб ×10 → 1200×400 PNG),
   загрузка тем же эндпоинтом.
4. **Лента «Последние действия»**: серверный журнал последних событий игрока, публичный.
5. **Вёрстка как в макете**: hero-шапка с наезжающим аватаром + две колонки карточек.

## Не цели

- Достижения, «победы в боях», «открытые зоны», «найденные предметы» — сервер этого
  не считает; правило карточки «без выдуманных чисел» остаётся. Блок достижений не делаем.
- Отдельные страницы «Все друзья» / «Вся активность».
- Анимированные GIF после кадрирования (станут статичными; GIF без кадрирования
  загрузить больше нельзя через UI — путь один, через кадр).
- Изменения в Пивных гротах (grotto) — там профилей нет.

## Анти-цели

- Не ломать существующий контракт `/banners/*` и лимиты сервера (≤1200×400, ≤2 МБ).
- Не раскрывать то, что скрыто приватностью сверх решения владелицы (логин, роль, sp,
  год рождения, комната-код). Название локации в ленте — да (решение владелицы 2026-11-14:
  «все, с локациями»).
- Не раздувать god-файлы: каждый файл ≤800 строк (`npm run arch:check`).

## Решения владелицы

- Делаем: шапку с кадрированием, ленту действий, вёрстку «как в макете», генерацию
  шапки при её отсутствии и возможность нарисовать.
- Ленту видят **все**, **включая переходы по локациям**.

## Подходы (рассмотрены)

**Шапка-кадрирование.**
- (выбрано) Кадр в браузере на `<canvas>` → `toBlob` → существующий upload. Сервер не меняется.
- Хранить оригинал + координаты кадра на сервере — гибче (перекадрировать без перезагрузки),
  но меняет сервер, хранилище и DTO ради редкого сценария.

**Шапка по умолчанию.**
- (выбрано) Процедурный пиксельный пейзаж на клиенте из seed=`accountId`.
- Набор готовых картинок в `public/` — проще, но одинаковые у многих и нужен арт.

**Рисование.**
- (выбрано) Пиксельный редактор-сетка — в стиле игры, легко получить красиво.
- Свободная кисть — сложнее сделать красиво мышью, не в стиле.
- Переиспользовать KNS Paint (`public/paint-demo/` + мост `game-bridge.js`, им уже
  рисуют окрасы) — мощнее, но копия KNS хранится байт-в-байт (гейт `check:paint-seam`),
  холст и мост заточены под спрайт кота; переделка под 1200×400 трогает чужой контракт.

**Лента действий.**
- (выбрано) Новый журнал `DATA_DIR/activity.json` — по образцу `server/notifications.js`
  (кольцевой буфер на аккаунт, атомарная запись).
- Выводить на лету из уже хранимых полей (createdAt, bannerAt, рёбра друзей) — без
  хранилища, но нет «зашёл в игру» и «переместился в локацию», ради которых лента и нужна.

## Как устроено

### Сервер: `server/activity.js` (новый)

- Хранилище `DATA_DIR/activity.json`: `{ v:1, byAccount: { [accountId]: Item[] } }`,
  `Item = { id, type, at, data }`, не более **20** на аккаунт (старые вытесняются).
  
- `pushActivity(accountId, type, data)` — единственный писатель. Типы и `data`:
  - `joined_site` `{}` — регистрация; не пишется, всегда синтезируется при отдаче из `createdAt`.
  - `entered_game` `{}` — heartbeat `where=game`, когда до него свежего game-heartbeat
    не было (`row.gameUntil <= now` до обновления) — в `server/presence.js`.
  - `moved` `{ locationId, label }` — успешный `travel()` в `server/location-world.js`
    (после `join`). `label` — та же строка, что `locationLabelOf` (`зона · место`).
  - `friend_added` `{ friendId, friendName }` — обеим сторонам при `accepted` в `server/friends.js`.
  - `avatar_changed` `{}` / `banner_changed` `{}` — успешный upload в `avatars.js` / `banners.js`.
- Схлопывание шума: если последнее событие того же типа (и для `moved` — с тем же
  `locationId`) было < 2 мин назад — обновить его `at`, а не добавлять новое.
  `entered_game` не чаще раза в 10 мин.
- Удаление аккаунта (`server/account-delete.js`) стирает его журнал.
- *Решения строителя (по итогам проверки документа):*
  - `entered_game` несёт `{ label }` текущей локации на момент входа («Зашёл в игру · Долина»);
    `moved` пишется только при успешном `travel()` через проход. Респаун и админский
    `join` редактора событий не дают.
  - Удаление из друзей (`friends.js` remove) вычищает `friend_added` об этой паре у обеих
    сторон — публичная лента не показывает бывших друзей.
  - Старые аккаунты: если в журнале нет `joined_site`, при отдаче он синтезируется из
    `createdAt` (миграции нет, ленты не пустые после деплоя).
  - `player-profile.tsx` (851, держится на исключении arch-гейта) не растёт: меню шапки,
    кадр и редактор — новые файлы; из него только убирается старое поле фона.
- Запись немедленная (`writeFileAtomic`, как notifications) — события редкие и схлопываются.
- Отдача: `GET /activity/:accountId` → `{ ok, items: Item[] }` (новые сверху), публично
  в зоне Элизий (как `GET /friends/:accountId`); клиент ходит через `/cfg/activity/...`
  (прод-nginx, как friends/banners). Имя друга в `friend_added` резолвится при отдаче
  из текущего профиля (переименования подхватываются), удалённый аккаунт → «кто-то».
- Маршрут регистрируется там же, где friends/notifications (`server/net.js`).
- Доки: таблица HTTP-маршрутов в `docs/PLATFORM-ARCHITECTURE.md`, новая строка данных
  в `docs/PRIVACY-DATA.md` (публичный журнал, включая названия локаций), строка в
  `AGENTS.md` (code-map + `check:landmarks`).

### Клиент

- `src/lib/net/http-activity.ts` — `httpActivity(accountId)`; литерал `/cfg/activity` только тут.
- `src/lib/sim/banner-gen.ts` — `generateBanner(seed): ImageData|canvas` 120×40 пикселей:
  seeded PRNG (mulberry32 от хэша `accountId`), вертикальный градиент неба из 3–4 ночных
  палитр, звёзды, луна (фаза/позиция от seed), 2–3 слоя холмов, силуэты деревьев/руин,
  кусты с цветами по краям. Рисуется в canvas с `image-rendering: pixelated`. Чистая функция —
  под unit-тест (детерминизм и размер).
- `src/components/players/banner-cropper.tsx` — модалка: файл (PNG/JPEG/GIF/WebP, любой
  размер в разумных пределах ~10 МБ на клиенте), drag мышью/тачем, ползунок зума
  (min = картинка закрывает рамку целиком), вывод 1200×400 JPEG q≈0.9 (PNG, если
  исходник PNG и результат < 2 МБ). Кнопки «Сохранить» / «Отмена».
- `src/components/players/banner-painter.tsx` — модалка-редактор 120×40: кисть 1/2/3 px,
  ластик (прозрачный → цвет неба), заливка, пипетка, палитра ~24 цвета ночной гаммы +
  произвольный цвет, отмена/повтор (стек ~50), «начать с моей сгенерированной шапки» /
  «чистый лист». Экспорт ×10 nearest-neighbour → PNG 1200×400 → upload.
- Меню шапки на своей карточке (кнопка на шапке, как «Изменить фон» в Твиттере):
  «Загрузить картинку…», «Нарисовать…», «Убрать шапку» (только если она есть).
  Существующее поле фона в настройках заменяем этим меню (один путь).
- `profile-card-view.tsx` — новая вёрстка; крупные куски выносим в отдельные файлы
  (`profile-hero.tsx`, `profile-activity.tsx`, `profile-friends-grid.tsx`), чтобы уложиться в 800 строк.

### Вёрстка (по макету)

```
[ ШАПКА 3:1 — своя или сгенерированная      (кнопка «Изменить шапку» — владельцу) ]
[ АВАТАР ]  Имя  [статус]               (В друзья / Принять …)
            о себе — первая строка
            (☾ N лун) (📅 На сайте с …) (● Онлайн)
[ Профиль ]                                         [ ⚙ Настройки профиля ] (владелец)
┌ Активный персонаж ──────────┐ ┌ Друзья · N ───────────────────────┐
│ имя ♀/♂ · персонаж на лугу  │ │ сетка аватаров с точкой статуса   │
├ Краткая статистика ─────────┤ ├ Последние действия ───────────────┤
│ дни на сайте · персонажей · │ │ иконка · текст · «17 минут назад» │
│ локация · время в игре ·    │ │ … до 20, пусто → «Пока тихо»      │
│ друзей                       │ └───────────────────────────────────┘
├ О себе ─────────────────────┤
└─────────────────────────────┘
```

- Палитра и стекло — существующие токены `players-elyria.module.css`; карточки с
  золотистой/фиолетовой рамкой как в макете. На узком экране (<760px) — одна колонка:
  персонаж, друзья, действия, статистика, о себе.
- Вкладка «Настройки» остаётся (редактор `OwnProfileEditor`), кнопка справа как в макете.
- «Луны» = существующий `existsDaysText`/playtime-пилюли — берём то, что уже есть.

## Проверка

- Unit: `banner-gen` (детерминизм, 120×40, разные seed → разные картинки),
  математика кадра (координаты выреза при зуме/сдвиге).
- `scripts/test-profile-social.mjs` (+ при необходимости отдельный `test-activity.mjs`):
  события пишутся (регистрация, game-heartbeat, друзья, баннер), схлопывание, лимит 20,
  публичная отдача, удаление аккаунта стирает журнал, grotto → 404.
- Все гейты из `AGENTS.md` «Gates».
- Ручная проверка в браузере (elyria-сборка локально): кадр, рисование, генерация,
  лента, мобильная ширина.

## Оставлено строителю

- Иконки событий (существующий набор иконок карточки или inline-SVG).
